How they fit together

One practice day, six commands

The skills are not a toolbox so much as a loop. Each one writes exactly one record and names the one it leaves for the next — so a solution, a practice attempt and a mastery verdict never end up in each other's file.

1/l3-core next 5pick today's problems from the fixed core set 2/lc-coachmock-interview it, get the verdict 3/lc-python · /lc-javafile the solution and its README row 4/lc-cheatsheetfile what it taught you 5/lc-logrecord the attempt in the practice log 6/lc-againpromote it only when re-derived unaided

↺ tomorrow, /l3-core reads the log you just wrote

Install

Pick the skills, pick the agent, copy one command

Inside a clone of this repo there is nothing to install — the skills are already at .claude/skills/ and Claude Code loads them. To use them anywhere else, build the command here.

Copied into your user-level skills folder, so every repo gets them.

git clone --depth 1 https://github.com/yennanliu/CS_basics.git /tmp/cs_basics
mkdir -p ~/.claude/skills
cp -r /tmp/cs_basics/.claude/skills/{lc-python,lc-coach,lc-log} ~/.claude/skills/

Under the hood

What a skill actually is

No runtime, no server. A skill is a directory an agent reads, and this repo checks every one of them in CI.

01A markdown recipe

SKILL.md carries a frontmatter description the agent matches your request against, an Invocation line, numbered steps, a Do not list and a worked example.

02The directory is the command

Renaming .claude/skills/lc-log/ renames /lc-log. Plain English works too — “log today's practice” loads the same skill.

03Gated like code

script/check_skills.py --install --run installs each skill into a temp dir, re-checks it alone, and runs the commands it tells an agent to type.
