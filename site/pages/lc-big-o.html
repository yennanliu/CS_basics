Rules for stating it in an interview

  1. Drop constants and lower-order terms. 3n² + 10n + 7 is O(n²). Two passes over the array is still O(n).
  2. Sequential steps add, nested steps multiply. A loop then another loop is O(a + b); a loop inside a loop is O(a · b).
  3. Different inputs get different letters. Comparing two strings is O(m · n), not O(n²); a graph is O(V + E). Collapsing them to n is the most common way to state a wrong bound.
  4. Halving gives a log. Whenever each step cuts the remaining work in half — binary search, a balanced tree, a heap — the step count is log n. The base never matters: log₂ n and log₁₀ n differ by a constant.
  5. Recursion is branchesdepth. Naive Fibonacci makes 2 calls, n deep: O(2ⁿ). Memoise it and each state is computed once: O(states × work per state) = O(n).
  6. Divide and conquer: split in half, do linear work to merge — O(n log n) (merge sort). Split in half and keep one side — O(log n) (binary search).
  7. Amortised counts the whole run. A dynamic array's occasional resize, or a monotonic stack where each item is pushed and popped once, is O(1) per operation over the run — say "amortised" out loud.
  8. Space includes the recursion stack. A DFS on a skewed tree is O(n) space even with no data structure in sight; on a balanced one it is O(log n).
  9. Name the line that sets it. "The sort is O(n log n) and everything after it is linear, so the total is O(n log n)" is the sentence an interviewer is listening for.
