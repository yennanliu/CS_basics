## 概觀

這個家族被三個問題主宰：*兩個節點在哪裡交會*（LCA）、*它們相隔多遠*（距離），
以及*哪些根到葉的路徑滿足某個性質*（路徑和／路徑長度）。三者都是一次 DFS——
差別只在那個數字是當參數**往下**走，還是當回傳值**往上**冒，以及你能不能**往上**走到父節點。

<!-- 14eb977aabc6 -->
### 關鍵性質
- **複雜度**：這裡所有模板都是 O(N) 時間；遞迴空間 O(H)，一旦建出父節點表或圖就是 O(N)
- **核心想法**：LCA 就是分岔點 — `dist(p, q) = dist(lca, p) + dist(lca, q)`
- **什麼時候用**：答案是一條路徑、一段距離或一個交會點，而不是某個子樹性質
- **哨兵規則**：距離的輔助函式在「找不到」時必須回傳 `-1`（不能是 `0`），因為 `0` 是一個合法的距離

## 模板與演算法

<!-- 9b6920dca5f9 -->
### Template 1: LCA by Returned Presence — LC 236

**辨識** — 「兩個節點 `p` 和 `q` 的最近共同祖先」、「同時以兩者為子孫的最深節點（節點可以是自己的子孫）」，有給根，而且保證兩個目標都存在。節點 ≤ 10⁵ → 一次 O(N) 走訪。

**關鍵** — 如果 `p` 或 `q` 在 `node` 的子樹裡，`dfs(node)` 就回傳它（兩個都在時回傳它們的 LCA），否則回傳 `None`。第一個**兩邊**呼叫都回傳非空的節點就是分岔點，所以它就是 LCA。當一個目標是另一個的祖先時，碰到它就提早 `return root` 已經是答案：另一個目標就在它下面某處。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(N)**：兩個遞迴呼叫每個節點最多拜訪一次；提早 `return root` 只會讓走訪更早結束。
- **空間 O(H)**：遞迴堆疊，每層一個 frame — 斜樹時 H = N。

**試跑** — `root = [3,5,1,6,2,0,8,null,null,7,4]`

<!--CODE-->

**陷阱**
- 只要**任一**邊非空就回傳 `root`：`p = 6, q = 4` 會讓 `dfs(3)` 回傳 `3`，而不是把從左邊拿到的 `5` 往上傳。
- 提早回傳的前提是兩個目標都存在。`q` 不存在時（LC 1644），`p = 5, q = 99` 仍會回傳 `5`；要改成數命中次數 — 見下面 LC 1644 的程式碼。
- 比 `root.val == p.val` 而不是比節點：值唯一時沒問題，一旦值重複就錯。要比節點本身。

**不適用時** — 樹是 **BST**：依值往下走，O(h)，永遠不用進兩邊子樹（[bst.md](./bst.md)，以及下面 LC 235 的程式碼）。**沒有根**而每個節點都有 `parent`：改成往上走（[LC 1650 變形](#lca-variant--parent-pointers-no-root-lc-1650-)）。

**練習** — LC 236 · LC 235 *（BST：往下走）* · LC 1650 *（沒有根：兩個指標往上）* · LC 1644 *（目標可能不存在：數命中次數）* · LC 1676 *（一組目標）* · LC 865 *（最深的節點就是隱含的目標）*

#### LCA 家族 — 用**手上有什麼**來挑模板 ⭐⭐⭐⭐⭐

這五題都在講「最近共同祖先」。但上面那個後序模板只適用第一列；其餘各改掉一個前提，
而那個前提就決定了解法的形狀。

| LC | 跟 236 差在哪 | 對應的形狀 | 複雜度 |
|----|--------------------|-----------------|------------|
| **236** | — （基準題：給 root，`p`、`q` 保證存在） | 後序，回傳「找到或 null」 | O(N) / O(H) |
| **235** | 樹是 **BST** | 不用兩邊都遞迴 — 只要 `p`、`q` 在同一側就**往下**走 | O(H) / O(1) |
| **1644** | `p`、`q` **可能不存在**於樹中 | 一樣的後序，但還要數看到幾個目標；只有 `count == 2` 才算答案 | O(N) / O(H) |
| **1650** | **沒有 root** — 每個節點有 `parent` 指標 | 往**上**走而不是往下 → 這就是 LC 160（兩條鏈結串列） | O(H) / O(1) |
| **1676** | 目標有 **N 個**而不是 2 個 | 一樣的後序，只是比對一個目標 `set` | O(N) / O(H) |

> **挑模板只要問一個問題**：*我能不能從某個 root 走到 `p` 和 `q`？*
> 能 → 往**下**遞迴（236 / 1644 / 1676）。如果我是*站在* `p`、`q` 上、手上只有
> `parent` 指標 → 往**上**走（1650）；這時根本沒有一棵樹可以搜。

**常見坑：**
- ❌ `a = a.parent or q` ／ `a = (a.parent != null) ? a.parent : q` — 這會**跳掉 `null` 那一步**。
  把 `null` 也走掉，才能讓兩邊的總步數相等；跳掉就永遠差一步，兩個指標會一直錯身而過。
- ❌ 用 `a.val != b.val` 而不是 `a != b` — 這題剛好可行，但你要的是節點的身分，
  值一旦重複就爆了。
- ❌ 以為 `p` 和 `q` 一定同根。若它們在**不同**的樹裡，兩個指標會在同一步一起落到 `null`，
  於是 `a == b == null`，迴圈結束回傳 `null` — 雙指標寫法白送你這個終止條件，
  單純同步往上的那種寫法沒有。
- ❌ 反射動作去拿後序模板。這裡根本沒有 `root` 參數可以傳給它。

#### LCA 變形 — 含所有最深節點的最小子樹（LC 865 / LC 1123） ⭐⭐⭐⭐

<!-- 544625ea8425 -->
##### **1. 核心想法**

**關鍵洞見**：這題其實是換皮的 LCA。它沒有直接給你目標節點 `p` 和 `q`，目標是**隱含的**——所有位於最大深度的節點。

<!--CODE-->

竅門在於**一次後序走訪同時算出兩件事**：你得走完整棵樹才知道哪些節點最深，
但同時又需要那些節點的 LCA。所以每次遞迴呼叫都回傳一個**配對**：

<!--CODE-->

`depth` 那一半就是 LC 104（`max depth`）。`lca_candidate` 那一半跟著它一起往上帶，
並在**每個節點都依兩邊深度重新決定一次**。

**三種情況**（這個比較本身就是整個演算法）：

| 情況 | 意義 | 回傳 |
|------|---------|--------|
| `left.depth > right.depth` | 最深的節點全在左邊 | `(left.depth + 1, left.node)` — 把左邊的答案往上冒 |
| `right.depth > left.depth` | 最深的節點全在右邊 | `(right.depth + 1, right.node)` — 把右邊的答案往上冒 |
| `left.depth == right.depth` | **兩邊**都有最深節點 | `(left.depth + 1, node)` — **當前節點就是 LCA** |

**情況 3 為什麼對**：兩邊都在同一個深度觸底，代表最深節點集橫跨當前節點，
所以沒有任何一個子節點能全部包住——當前節點就是能包住它們的最小子樹。
而且只要往上的路上又出現深度打平，答案就會被覆寫，所以最後根呼叫拿到的是*最低*的那一個。

**情況 1/2 為什麼對**：如果有一邊嚴格更深，那較淺的那邊根本沒有最深節點，
所以答案完全落在較深的子樹裡——原封不動往上傳就好（**不要**換成當前節點）。

**base case**：`dfs(null) -> (0, None)`。null 子節點深度為 0，會讓葉子透過情況 3 回傳
`(1, leaf)`——一個葉子當然是它自己的 LCA。

##### **2. 模式：後序 DFS 回傳 `(metric, payload)`**

這是它的一般化形狀——**由下往上聚合，同時帶著一個候選答案**。
只要題目說*「滿足…的最小子樹」*或*「兩側極端交會的那個節點」*，就掏這招出來。

<!--CODE-->

**模式檢查清單：**
- **走訪順序**：後序（必須先知道兩個子節點才能決定）
- **回傳型別**：tuple／輔助類別——一個*純量指標*＋一個*節點參照*
- **決策依據**：比較兩個子節點的指標，絕不靠全域狀態
- **不做第二趟**：不要先算最大深度再重掃一次；一趟就夠了
- **time = O(N)**、**space = O(H)** — H = 樹高（遞迴堆疊）

> **和「全域變數」風格的對比**（LC 543 / LC 124）：那類題目只回傳一個純量，
> 答案藏在成員變數裡。這裡我們把答案放*在 tuple 裡*回傳，因為答案是在往上的路上
> 被**挑選**出來的，不是被取最大值取出來的。

**常見陷阱：**
- ❌ 情況 1/2 也回傳 `node` → 你永遠只會拿回根節點
- ❌ 打平那個情況用 `>=` 而不是 `==` → 錯誤地把情況 1 併進情況 3
- ❌ 走兩趟（先找最大深度，再找該深度所有節點的 LCA）→ 可行，但多花 O(N) 空間、程式碼也長得多

### Template 3: Distance Between Nodes via LCA — LC 1740

**辨識** — 「值為 `p` 與 `q` 的兩個節點之間路徑上的邊數」，有給根，值不重複。節點 ≤ 10⁴ → O(N)。

#### **`get_dist` — 為什麼用 `-1`，以及為什麼加總永遠正確**

**「找不到」為什麼要用 `-1` 而不是 `0`？**

| 回傳值 | 意義 |
|--------------|---------|
| `0`          | **合法** — 目標就在當前節點（相隔 0 條邊） |
| `dist > 0`   | **合法** — 目標在起點下方 `dist` 條邊處 |
| `-1`         | **哨兵** — 目標不在這一支裡（死路） |

如果「找不到」回傳 `0`，那就沒辦法區分*「就在這裡，距離 0」*和*「找不到」*。所以 `0` 被保留給真正的距離，`-1` 是唯一安全的「找不到」旗標。

**合法距離是怎麼往上冒的（前序 DFS）：**
1. 碰到 `None` → 回傳 `-1`（這條路是死路）。
2. 碰到目標 → 回傳累積的 `dist`（一個 ≥ 0 的邊數）。
3. 否則帶著 `dist + 1` 遞迴 `left`／`right`。
   - `left != -1` → 目標在左子樹，**立刻**把那個距離往上傳（短路，跳過右邊）。
   - 否則回傳 `right`（不是右子樹的合法距離，就是兩邊都失敗的 `-1`）。

##### **該用哪一個？**

- **面試／講清楚** → **V1**（面試官想看的就是你怎麼推理哨兵的處理）
- **想寫得短、一行漂亮解** → **V2**（記得主動說出你放棄了短路）

- ❌ `None` 回傳 `0` 而不是 `-1` → 沒辦法區分「就在這個節點找到」和「找不到」
- ❌ 漏了 `if left != -1: return left` 這個守衛 → 回傳了右子樹的 `-1`，把找到的距離弄丟
- ❌ 在傳 depth 的版本裡又加 `+1` → 重複計數（往下的路上已經加過了）
- ❌ 從 `root` 而不是從 `lca` 呼叫 `get_dist` → 量到的是錯的路徑

<!--CODE-->

**策略 2：可變 List — 原地修改，然後回溯**

路徑是可變結構（`list`、`List<Integer>`、`StringBuilder`）時，**同一個物件**會被所有呼叫共用，所以每次修改都要在呼叫返回時還原。那正是上面 Template 4 的程式碼：遞迴前 `path.append`／`path.add`，遞迴後 `pop`／`remove`。

**比較：**

| 面向 | 不可變字串 | 可變 List＋回溯 |
|--------|-----------------|--------------------------|
| 路徑在哪裡更新 | 在 DFS 呼叫的參數裡 | 在 DFS 呼叫之前 |
| 需要回溯嗎？ | 不用（每層都有自己的副本） | 要（必須還原修改） |
| 記憶體 | 每條路徑產生 O(N) 個新字串 | O(N)，共用同一個重複利用的 list |
| 最適合 | 字串路徑（LC 257） | 數值路徑（LC 113、112） |
| 出 bug 的風險 | 低（沒有共用狀態） | 中（容易忘記回溯） |

**經驗法則：**
- **不可變（String、int）** → 在呼叫裡把更新後的值傳下去 → 不用回溯
- **可變（List、StringBuilder）** → 呼叫前修改 → 呼叫後回溯

<!-- 5f4d3dd1e94d -->
### Template 5: Downward Path Count with a Prefix-Sum Map — LC 437

**辨識** — 「值的總和為 `targetSum` 的路徑**數量**；路徑不必從根開始、也不必在葉子結束，但必須往下走」。節點 ≤ 1,000 而且值可能是負的，所以會縮的視窗行不通 → 用 map 做到 O(N)。

**關鍵** — `prefix` 只記**當前根路徑**上那些節點的「根到節點」總和的次數。一條在這個節點結束的往下路徑總和等於 `target`，若且唯若 `cur - target` 是其中之一 — 這就是樹上的 LC 560 — 而且回程時把計數還原，所以兄弟分支永遠不會和這一支配對。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(N)**：每個節點拜訪一次，做期望 O(1) 的 map 操作。
- **空間 O(N)**：map 對每個看過的不同前綴和留一個 key（只有當前路徑上的計數非零），再加上 O(H) 的遞迴。

**試跑** — 鏈 `1 → 2 → 3`，`targetSum = 3`

<!--CODE-->

**陷阱**
- 漏了 `prefix[0] = 1`：從根開始的路徑永遠算不到 — 上面那條鏈會回傳 1。
- 回程沒有減回去：左子樹的前綴和會和右邊的節點配對，把一條在父節點轉彎的路徑也算進去。`root = [0,1,3]`、`targetSum = 2` 會回傳 1，而不是 0。
- 先插入 `cur` 再查：`targetSum = 0` 時，每個節點都會把自己算成一條空路徑。
- Java 的 `int` 總和：LC 437 的值可達 ±10⁹，累加會溢位；map 的 key 要用 `long`。

**不適用時** — 路徑必須從根開始、在葉子結束 → [Template 4](#template-4-root-to-leaf-path-with-backtracking--lc-113)，不需要 map。輸入是陣列而不是樹 → LC 560 的前綴和，沒有東西要還原。這個樹版本更長的說明，包含 base case 的兩種寫法，在 [prefix_sum_advanced.md Template 14](./prefix_sum_advanced.md#template-14-prefix-sum-on-a-tree-dfs--hashmap--backtrack---lc-437)。

**練習** — LC 437 · LC 112 *（只要根到葉：不需要 map）* · LC 560 *（同一招用在陣列上）* · LC 1171 *（鏈結串列裡總和為零的連續段：同一張前綴 map）*

**和根到葉回溯的關鍵差異：**

| 模式                      | 路徑限制          | 資料結構        | 回溯什麼？         |
|------------------------------|--------------------------|-----------------------|-------------------------|
| DFS＋路徑 list＋回溯  | 只能根 → 葉         | `List<Integer>` path  | 移除最後一個元素     |
| DFS＋前綴和＋回溯 | 任意節點 → 任意節點 ↓   | `Map<Long, Integer>`  | 把 map 的計數減一     |

### Longest Univalue Path — LC 687

> **關鍵** — 一條臂只能穿過兩端值相同的邊繼續延伸。所以在記錄轉彎 `left + right` 之前，子節點的臂在 `child.val == node.val` 時加一，否則歸零。答案數的是**邊**。

**歸約到**：[binary_tree § Template 5](./binary_tree.md#template-5-height-up-answer-in-a-global--lc-543) — 臂穿過值不同的邊就歸零。

**陷阱**
- 子節點值不同就不往下遞迴：那棵子樹裡仍可能有答案。`[1,4,5,4,4,null,5]` 的答案 2 來自根（值 1）底下的 `4-4-4`。
- 數節點而不是數邊：單一節點是 0，不是 1。

### Closest Leaf in a Binary Tree — LC 742

> **關鍵** — 最近的葉子可能在節點 `k` 的**上方**（經過父節點再往另一支下去），所以先把樹變成無向圖。接著從 `k` 做 BFS，節點依距離順序被走到，第一個彈出的葉子就是答案。

**歸約到**：[Template 2](#template-2-parent-map--bfs--lc-863) — 同樣的父節點邊與 BFS，只是停在第一個沒有子節點的節點，而不是走 `k` 輪。

<!--CODE-->

**陷阱**
- 從 `root` 開始 BFS：找到的是離根最近的葉子。`[1,2,3,4,null,null,null,5,null,6]`、`k = 2` 必須回傳 3（往上兩條邊再過去），而不是 2 那條鏈底下的葉子。
