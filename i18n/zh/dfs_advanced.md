## 總覽

這些 DFS 模式在整個面試循環裡**只會出現一次**，不是每一關都考。每一個都是 [dfs.md](./dfs.md)
的某個核心模板，再加一項額外的記帳 — 第二張網格、一個方向旗標、一個累計總數、一個會分岔的字典樹查詢、
一組距離桶、一個以深度為索引的堆疊、一份深度備忘錄 — 而且每一個都能從題目認出來，因為題目會點名那個

這裡大多數輸入都到 n = 10⁵，在路徑形狀的輸入上，遞迴的 Python DFS 會超過預設的 1,000 層上限。
所以下面只要可能發生這種情況的模板，都用明確的堆疊來寫。

### Template 1：帶有效旗標的洪水填充 — LC 1905

**辨識** — 兩張形狀相同的網格；「數 `grid2` 裡、在 `grid1` 也全是陸地的島嶼」（子島嶼），或任何
「只有每一格都通過檢查的分量才算數」的題目。m, n ≤ 500，所以一座島可以有 250,000 格。

**關鍵** — 把 `grid2` 的整座島淹完，並把每一格的檢查結果 AND 進同一個旗標。就算旗標已經變成 false，
這座島也必須淹到底：沒被淹到的格子之後會被當成一座「新」島，被單獨計數。

<!--CODE-->

**複雜度**
- **時間 O(m·n)**：格子在推入之前就被設成 0，所以 `while stack` 迴圈每個陸地格子只彈出一次，
  並看 4 個鄰居。
- **空間 O(m·n)**：堆疊可能放得下一整座島。

**陷阱**
- 寫成 `return dfs(up) and dfs(down) and ...` 的遞迴版本，在第一個 false 就短路，
  島上其餘格子都沒被淹；那些格子之後會被當成另一座島計數。遞迴時必須寫
  `ok = dfs(nbr) and ok`（先呼叫），四個方向都要。
- 滿格網格上遞迴洪水填充深達 250,000 層：超過 Python 的預設上限，也很可能超過 Java 預設的
  執行緒堆疊。明確的堆疊沒有這個限制。
- 輸入會被修改（`grid2` 被淹掉）。呼叫端還需要它的話先複製一份。

**練習** — LC 1905 ⭐ · LC 1254 *（檢查條件是「從不碰到邊界」：[dfs.md § Template 7](./dfs.md#template-7-2-pass-dfs-boundary-elimination--lc-1254)）* · LC 827 *（替每座島標上大小，再逐一嘗試每個 0）*

### Template 2：在無向走訪上帶方向旗標 — LC 1466

**辨識** — 一棵由單行道組成的樹；「最少要反轉幾條路，讓每個城市都能到達城市 0」。
n ≤ 5·10⁴，共 n − 1 條邊。

### Template 3：跨連通分量的配對計數 — LC 2316

**辨識** — 「彼此無法到達的節點對數」、「分屬不同群組的配對」。n ≤ 10⁵ 排除了逐對檢查；
只有分量大小重要。

**關鍵** — 新分量的每個節點，都和之前已看過的分量裡每個節點配成一對，所以加上
`size × seen_so_far`，然後再讓 `seen_so_far` 變大。每個跨分量的配對只在找到它的第二個分量時被計一次。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(n + E)**：外層 `for start` 每個分量發動一次洪水填充，每個節點只推入一次。
- **空間 O(n + E)**：鄰接表、`seen` 和堆疊。

**陷阱**
- Java 的 `int` 會溢位：沒有邊且 n = 10⁵ 時答案約 5·10⁹。`pairs`、`size` 和 `seenSoFar`
  都要用 `long` — 兩個 `int` 相乘的 `size * seenSoFar` 會在轉型之前就溢位。
- 對每個分量加總 `size × (n − size)` 會把每對算兩次；要除以 2，或改用累計總數。
- 併查集也能得到同樣的大小（全部 union 完再數根），而且在邊一條一條加入時更合適。

**練習** — LC 2316 ⭐ · LC 323 *（只數分量個數）* · LC 2492 *（節點 1 所在分量裡的
最小邊）*

### Template 4：查詢會分岔的字典樹 DFS — LC 211

**辨識** — 一本單字字典，加上「`.` 可以匹配任何字母」、「恰好差一個字元」、「魔法字典」。
插入就是普通的字典樹迴圈；只有搜尋會分岔。單字 ≤ 25 個字母，LC 211 每個查詢最多 2 個點。

**關鍵** — `dfs(node, i)` 回答「`word[i:]` 能不能從這個字典樹節點開始匹配」。字母只走一個子節點；
`.` 嘗試每個子節點，第一次成功就回傳。查詢走完時，答案是有沒有單字在那個節點**結束**，而不是 `True`。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間**：`addWord` 走 L 個字母。`search` 每個字母只走一個子節點，但每個 `.` 會讓
  `for key, child` 迴圈跑過最多 26 個子節點，所以 d 個點在最壞情況是 O(26^d · L)。
- **空間 O(總字元數)**：每個不同的前綴一個字典樹節點；遞迴深度 L。

**陷阱**
- 查詢走完就回傳 `True`，會讓 `"ba"` 匹配到 `"bad"` 的前綴。要檢查結尾標記。
- 用 dict 實作字典樹時，`'$'` 標記也是其中一個鍵：`.` 迭代子節點時要跳過它，
  否則 DFS 會遞迴進 `True`。
- 第一個成功的分支沒有立刻回傳，會讓 26^d 的最壞情況變成每次都發生。

**不適用時** — 查詢沒有萬用字元：那就是普通的字典樹走訪（[trie.md](./trie.md)），
或乾脆用單字的雜湊集合。

**練習** — LC 211 ⭐ · LC 208 *（普通的字典樹）* · LC 676 *（見下）* · LC 212 *（由字典樹驅動的
網格 DFS）*

### Template 5：後序距離桶 — LC 1530

**辨識** — 「最短路徑不超過 `distance` 的葉節點對」，上界很小（`distance ≤ 10`），樹最多 2¹⁰ 個節點。

**關鍵** — 每個節點回傳 `cnt[d]` = 它下面恰好 `d` 條邊遠的葉節點數。左邊深度 `d1` 的葉節點和右邊深度
`d2` 的葉節點，經過這個節點相距 `d1 + d2 + 2`，而這個節點就是它們的最低共同祖先，所以每一對恰好在
這裡被計一次。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(N·distance²)**：N 個節點每個都跑一次 `d1` / `d2` 雙層迴圈。對 `right` 做累計前綴和，
  可以讓合併變成 O(distance)，總共 O(N·distance)。
- **空間 O(N + distance·height)**：遞迴深度，加上每個尚未結束的呼叫各一個桶。

**陷阱**
- 桶往上平移時會丟掉比 `distance` 更深的葉節點（是 `range(distance)`，不是
  `range(distance + 1)`）；在 `d = distance` 時寫 `cnt[d + 1]` 會越界。
- 在每個祖先都合併、而不是只在左右分岔處合併，會重複計數；這一對只屬於它們的 LCA。

**不適用時** — 距離上界很大：每個節點的桶都變成 O(N)。把樹轉成圖、從每個葉節點跑有界的 BFS
是比較慢的備案（O(L·N)），這些筆記裡沒有寫出它。

**練習** — LC 1530 · LC 543 *（在每個節點合併深度）* · LC 124 *（合併最佳向下總和）* · LC 687 ·
LC 1530 ⭐

### Template 6：N 元樹後序彙總 — LC 3965

**辨識** — 以 `edges` 給出、「`u` 是 `v` 的父節點」、根在 0 的樹；節點的值是子節點值（最小、最大、總和）
加上自己權重的某個公式；只問根的值。n ≤ 10⁵。

**關鍵** — 節點要等所有子節點都算完才能算。把 DFS 順序反過來彈出，每個子節點都會比它的父節點先被處理，
所以一個存放完成值的陣列就能取代遞迴。LC 3965 的公式：`own = (latest − earliest) + baseTime[node]`、
`finish = latest + own`，其中 `latest` / `earliest` 取自子節點。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(n)**：每個節點只推入一次，`for node in reversed(order)` 那一趟每個子節點串列只讀一次。
- **空間 O(n)**：子節點串列、`order`、`finish` 和堆疊。

**陷阱**
- 把圖建成無向的會破壞葉節點判斷：每個非根節點都會把父節點當成鄰居，沒有節點看起來像葉子。
- Java 的 `int` 會溢位：節點的值接近它最慢子節點的兩倍，隨深度不斷累積。題目只保證答案
  < 2⁵³；要用 `long`。
- 遞迴的 `dfs(child)` 寫法最容易解釋，但在一條鏈上深達 10⁵ 層；說明這一點，然後寫以順序為基礎的版本。

**不適用時** — 樹是二元的 `TreeNode`：同樣的彙總就是
[dfs.md § Template 6](./dfs.md#template-6-bottom-up-post-order-dfs--lc-543-)，遞迴深度是樹高。

**練習** — LC 3965 ⭐ ·
LC 3967 *（同樣的彙總，要回答很多個查詢）* · LC 559 *（1 + 子節點最大深度）* · LC 1376 *（子節點最大值 + 自己的時間）*

### Template 7：以深度為索引的堆疊 — LC 388

**辨識** — 輸入字串**本身就是**一棵樹：以 tab 縮排的行、以 `/` 分隔的路徑、每個 token 前面有一個深度
前綴。答案是根到葉的某種彙總，例如最長路徑。

**關鍵** — `stack[d]` 存放深度 `d` 那個尚未關閉的祖先的彙總值。處理深度為 `d` 的一行之前，
先彈到 `len(stack) == d + 1`：那些彈出就是 DFS 往上返回，而 `stack[d]` 這時正好是這一行的父前綴。
從頭到尾都不用建樹。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(N)**：`split` 和 `lstrip` 每個字元只讀一次；每個目錄最多被
  `while len(stack) > depth + 1` 迴圈推入、彈出各一次。
- **空間 O(D)**：堆疊為每個尚未關閉的目錄存一個項目。

**陷阱**
- 把檔案推入堆疊會弄壞所有更深的前綴；檔案是葉子。
- 完全沒有檔案時回傳 0（`"a"` → 0），不是最長的目錄路徑。
- `+ 1` 是**目錄**貢獻的 `/`，所以最上層的檔案以 `stack[0] = 0` 計分，前面沒有斜線。

**練習** — LC 388 ⭐ · LC 1233 *（見下）* · LC 1028 *（深度由破折號表示：把樹重建出來）*

### Template 8：在 parent 陣列上記憶化往上爬 — LC 4015

**辨識** — 樹以 `parent[]`（或 `manager[]`）給出，`parent[root] = -1`，而答案需要每個節點的深度或
樹高。n ≤ 10⁵，而且編號不保證 `parent[i] < i`。

**關鍵** — `parent[]` 本身就是往上的邊，所以 `depth[x] = depth[parent[x]] + 1` 不需要任何其他結構。
把它記憶化：每個節點的深度只算一次，每次往上爬都停在第一個已知的祖先，所以全部的爬升加起來是 O(n)。
深度從 1 開始，所以 `depth[x] == 0` 代表「還沒算」。

- **時間 O(n)**：節點只在 `depth[x] == 0` 時才被加入 `chain`，並在鏈展開時被填好，

**陷阱**
- 沒有備忘錄時，路徑形狀的樹要花 1 + 2 + … + n = O(n²)。
- 只掃一次 `i = 0 … n − 1`、寫 `depth[i] = depth[parent[i]] + 1`，只有在 `parent[i] < i` 時才對；
  LC 4015 不保證這點，所以這樣掃會讀到還沒填的項目。
- 遞迴往上爬在一條鏈上深達 n 層；n = 10⁵ 時需要明確的堆疊。

**不適用時** — 答案需要子樹彙總（大小、總和、子節點最小／最大）：把 `parent[]` 反轉成子節點串列，
改用 [Template 6](#template-6-n-ary-post-order-rollup--lc-3965)。
往上爬看起來也很像併查集的 `find`，但這裡沒有 `union`；用 DSU 毫無好處。

**練習** — LC 4015 ⭐ · LC 1376 *（沿著 manager 鏈累加時間）* · LC 1483 *（把往上爬以 2^k 步預先算好：
binary lifting）* · LC 1650 *（兩條鏈一起往上爬：兩串列交點）*

| Template 1（有效旗標） | [dfs.md § Template 2](./dfs.md#template-2-graph--grid-dfs-flood-fill--lc-200-) | 只有一張網格，每個分量都算數 |

| Template 3（配對計數） | [graph.md § Template 1](./graph.md#template-1-connected-components-by-traversal--lc-547-) | 只要分量的個數 |
| Template 4（字典樹 DFS） | 單字的雜湊集合，或普通的字典樹走訪 | 查詢沒有萬用字元，或字典小到可以逐字比較 |
| Template 5（距離桶） | [dfs.md § Template 6](./dfs.md#template-6-bottom-up-post-order-dfs--lc-543-) | 答案是一條最佳路徑（直徑、最大路徑和），不是配對數 |

| Template 7（以深度為索引的堆疊） | 先建樹，再對它 DFS | 面試官要的是樹本身，或格式不是一個節點一行 |

## 總結

| 模板 | 額外記帳 | 時間 | 空間 |
|---|---|---|---|
| 1. 有效旗標 | 每次洪水填充一個布林值 | O(m·n) | O(m·n) |
| 2. 方向旗標 | 每條存起來的邊上的 `0/1` | O(n) | O(n) |
| 3. 配對計數 | 已看過節點的累計總數 | O(n + E) | O(n + E) |
| 4. 字典樹 DFS | 遇到 `.` 分岔／不匹配額度 | 每次搜尋 O(26^d · L) | O(總字元數) |
| 5. 距離桶 | 每個節點的 `cnt[d]` | O(N·d²) | O(N) |
| 6. N 元樹彙總 | 用反向前序取代遞迴 | O(n) | O(n) |
| 7. 以深度為索引的堆疊 | 每個尚未關閉的祖先一個 `stack[d]` | O(N) | O(D) |
| 8. 記憶化往上爬 | `depth[]` 備忘錄，0 = 還沒算 | O(n) | O(n) |

**這份文件特有的陷阱**
- 結果是一個旗標的洪水填充，仍然要把整個分量淹完。
- 字典樹 DFS 要檢查單字結尾標記，迭代子節點時又要跳過它。
- 以深度為索引的堆疊從不推入葉子。
- n 到 10⁵ 且輸入可能是路徑形狀：Templates 1、2、3、6 和 8 因此都用明確的堆疊來寫。

### 語言備註
- **Python 遞迴**：預設上限是 1,000 層。`sys.setrecursionlimit(10**6)` 可以調高，但很深的遞迴仍可能
  耗盡 C 堆疊；明確的堆疊才是安全的寫法。
- **Java 遞迴**：LeetCode 解答沒辦法設定執行緒堆疊大小；數萬層就可能丟出 `StackOverflowError`。
- **Java 共享狀態**：傳進遞迴呼叫的 `StringBuilder`、`List` 或 `int[]`，在每一層都是同一個物件，
  所以呼叫返回後 append 的內容還在 — [dfs.md § Template 8](./dfs.md#template-8-path-signature-shape-encoding--lc-694)
  就是這樣建出路徑簽名的。`int` 或 `String` 參數是副本；改用回傳值。
