## 總覽
**動態規劃**是一種演算法典範：把複雜問題拆成較簡單的子問題，並把子問題的答案存起來，避免重複計算。

<!-- 31f3313d80b2 -->
### 關鍵性質
- **時間複雜度**：因題而異，通常是 O(n²) 或 O(n³)
- **空間複雜度**：記憶化表格通常是 O(n) 到 O(n²)
- **核心想法**：把重疊的子問題記下來，用空間換時間
- **什麼時候用**：具備最佳子結構與重疊子問題的題目
- **關鍵技巧**：記憶化（由上而下）與表格化（由下而上）

<!-- 944959d4d3dc -->
### 核心特徵
- **最佳子結構**：最佳解由子問題的最佳解組成
- **重疊子問題**：同一個子問題被算很多次
- **記憶化**：把結果存起來，避免重算
- **狀態轉移**：定義狀態之間的關係

- 核心變數：`state`、`transition`
- 轉移需要知道的任何東西，都可以放進 `state`

## 題型分類

<!-- 3731628845de -->
### **分類 1：線性 DP**
- **說明**：單一序列、相依關係呈線性的題目
- **範例**：LC 70（Climbing Stairs）、LC 198（House Robber）、LC 300（LIS）
- **模式**：dp[i] 依賴 dp[i-1]、dp[i-2] 等等
- **子型態 — 前綴切分**：dp[i] 改成掃過*每一個*切點 j < i，並檢查整段 s[j:i] —
  LC 139（Word Break）、LC 132、LC 279。見 [Template 1b](#template-1b-prefix-partition-dp--lc-139-)。
- **子型態 — 以值為鍵（DP + 雜湊表）**：x 唯一合法的前一個元素是某個已知的值
  （x - d），所以 dp 存在以「值」為鍵的雜湊表裡，內層迴圈就消失了 — LC 1218。見 [Template 7a](#template-7a-value-keyed-dp-dp--hash-map--lc-1218-)。

<!-- a05f8caf7ae7 -->
### **分類 2：格子／二維 DP**
- **說明**：在二維格子或矩陣上的題目
- **範例**：LC 62（Unique Paths）、LC 64（Minimum Path Sum）、LC 221（Maximal Square）
- **模式**：dp[i][j] 依賴鄰居

<!-- 35d91195adc0 -->
### **分類 3：區間 DP**
- **說明**：在區間或子陣列上的題目
- **範例**：LC 312（Burst Balloons）、LC 1000（Minimum Cost to Merge Stones）
- **模式**：dp[i][j] 表示區間 [i, j]

<!-- 420569c8ed6e -->
### **分類 3-2：賽局理論／Minimax DP** → [dp_advanced.md](./dp_advanced.md)
- **說明**：兩名玩家在陣列上做最佳決策；每人只能從頭或尾取
- **範例**：LC 486（Predict the Winner）、LC 877（Stone Game）、LC 1140（Stone Game II）
- **模式**：`dp[i][j]` = 在 `nums[i..j]` 上的最大相對分差（當前玩家減對手）
- **遞迴式**：`dp[i][j] = max(nums[i] - dp[i+1][j], nums[j] - dp[i][j-1])` — 推導與模板見 [dp_advanced.md](./dp_advanced.md)

<!-- 363e64a84047 -->
### **分類 4：樹上 DP**
- **說明**：在樹狀結構上做 DP
- **範例**：LC 337（House Robber III）、LC 968（Binary Tree Cameras）
- **模式**：每個節點的狀態取決於它的子節點
- **📚 實作方式**：樹上 DP 靠 DFS 走訪來實作。DFS 的走訪模式見 **dfs.md 模板 6（由下而上的 DFS）**

- **子模式**：由下而上（後序）的樹上 DP，以及換根 DP（兩趟 DFS）— 都在 [dp_advanced.md](./dp_advanced.md)

### 模板 1：一維線性 DP — LC 53 ⭐⭐⭐⭐⭐

**辨認** — 一個陣列，而位置 `i` 的答案只取決於**固定幾個更早的位置**：「連續子陣列的最大和」、
「走到第 n 階的方法數」、「不能拿相鄰的兩個」。n ≤ 10⁵ → 預期是一趟 O(n)。

**關鍵** — `dp[i]` 講的是**恰好結束在 `i`** 的子陣列，所以它只有兩個選擇：接上結束在 `i-1`
的最佳那一段，或是從 `i` 重新開始。答案可以結束在任何地方，所以是 `max(dp)`，不是 `dp[n-1]`。

- **狀態**：`dp[i]` = 恰好結束在索引 `i` 的子陣列的最大和
- **遞迴式**：`dp[i] = max(nums[i], dp[i-1] + nums[i])`
- **基底**：`dp[0] = nums[0]`
- **順序**：`i` 遞增 — `dp[i]` 只讀 `dp[i-1]`
- **答案**：`max(dp)`

**陷阱**
- `dp[i] = max(dp[i-1], nums[i])` 漏掉了 `+ nums[i]`，回傳的是**最大的元素**而不是最大的和：
  `[1, 2]` 會給 2 而不是 3。
- 回傳 `dp[n-1]` 等於假設最佳的一段結束在最後一個索引：`[5, -9]` 會回傳 -4 而不是 5。
- 把 `best` 初始化成 0（或 `dp` 全填 0），在每個值都是負數時就錯了：`[-3, -1]` 必須回傳 -1。

**不是這個，如果** — 前驅可以是**任何**更早的索引，而不只是 `i-1` → LIS
（[模板 7](#template-7-longest-increasing-subsequence--lc-300-)）。如果是乘積而不是和，就要同時帶著
結束在 `i` 的最大值與最小值 → [kadane_algorithm.md](./kadane_algorithm.md) 裡的 LC 152。

**練習** — LC 53 ⭐ · LC 746 *（取 min 而不是 max，往回兩步）* · LC 152 ⭐ *（同時帶著 max 與 min）* ·
LC 918 *（環狀：總和 − 最小子陣列）* · LC 1191 *（重複的陣列）*

### 模板 1a：以長度為索引的表格（n + 1 格）— LC 70

**辨認** — 答案講的是**前 `i` 個項目**或**大小為 `i` 的目標**，而且大小 0 本身就有一個有意義的答案：
「走到第 `n` 階的方法數」、「前 `i` 個字元能不能……」、「湊出金額 `a` 的最少硬幣數」。
訊號是有一個代表*什麼都沒有*的 base case。

**關鍵** — `dp[i]` 講的是一個**長度**（或金額），不是索引 `i` 上的那個元素。第 0 格放的是空前綴，
所以表格有 `n + 1` 格，第 `i` 步決定的元素是 `nums[i-1]`，而答案是 `dp[n]`。

- **狀態**：`dp[i]` = 站上第 `i` 階的不同方法數
- **遞迴式**：`dp[i] = dp[i-1] + dp[i-2]` — 最後一步走了一階或兩階
- **基底**：`dp[0] = 1`（原地不動算一種），`dp[1] = 1`
- **順序**：`i` 遞增，`2 → n`
- **答案**：`dp[n]`

<!--CODE-->

**複雜度**
- **時間 O(n)**：`for i in range(2, n + 1)` 跑一趟，每一階 O(1)。
- **空間 O(n)**：`n + 1` 格的表。兩個滾動變數可以讓它變成 O(1)
  （[模板 6](#template-6-memoization--tabulation--rolling-variables--lc-198-)）。

**陷阱**
- 三個訊號必須一致 — `[0] * (n + 1)`、`range(1, n + 1)`、`return dp[n]`。長度觀點和索引觀點混用，
  不是讀到超出字串尾端的 `s[n]`，就是漏掉最後一個元素。
- 在以長度為索引的迴圈裡，`s[i-1]` 是**目前**這個字元，不是前一個（見下）。
- 沒有防護就初始化 `dp[2]`：`n = 1` 時表只有 2 格，`dp[2] = …` 會丟出 `IndexError`。只初始化
  `dp[0]` 與 `dp[1]` 就只需要 `n ≥ 1`。

**不是這個，如果** — `dp[i]` 講的是**位在**索引 `i` 的元素（「結束在 `i` 的子陣列」）→ 大小是 `n`，
用 [模板 1](#template-1-1-d-linear-dp--lc-53-)。每一步都要檢查一整段 `s[j:i]` →
[模板 1b](#template-1b-prefix-partition-dp--lc-139-)。

**練習** — LC 70 ⭐ · LC 746 *（dp[n] 是「頂端」，在最後一階的再下一格）* · LC 198 ⭐ *（下面的 n + 1 寫法）* ·

#### DP 還是 Dijkstra — 單向移動 vs 四向移動

| | LC 64（Min Path Sum，最小路徑和） | LC 1631（Min Effort Path，最小體力消耗路徑） |
|---|---|---|
| **移動方向** | 只能往右 + 往下 | 四個方向都可以 |
| **成本** | 累加總和 | 各步高低差的最大值 |
| **會重走格子嗎？** | 不會（單向） | 會（可能有更好的路徑） |
| **演算法** | 二維 DP | Dijkstra + min-heap |
| **需要 `visited` 嗎？** | 不需要 | 需要 |
| **DP 為什麼行得通** | 沒有環，是 DAG 結構 | DP 會失效：可以重走 |

**規則**：移動被限制成單向（往右／往下）→ 用**二維 DP**。四個方向都能走 → 用 **Dijkstra**（或帶優先佇列的 BFS）。

#### 決定迴圈順序的那條規則

> 先把轉移式寫出來。**右手邊**每一個 `dp[...]` 都是一支指*進* `dp[i][j]` 的箭頭。一種迴圈順序
> 合法，當且僅當每支箭頭都落在**已經填好**的格子上。就只有這樣而已。

| 轉移式讀到 | 是哪個鄰居 | 迴圈就必須 |
|---|---|---|
| `dp[i-1][j]` | **上**一列 | `i` 遞增（`1 → m`） |
| `dp[i+1][j]` | **下**一列 | `i` **遞減**（`n-1 → 0`） |
| `dp[i][j-1]` | **左**一行 | `j` 遞增（`1 → n`） |
| `dp[i][j+1]` | **右**一行 | `j` **遞減** |
| `dp[i+1][j-1]` | **內縮**後的區間（兩端各往內一格） | `i` 遞減**且** `j` 遞增 |
| `dp[i][k]`、`dp[k][j]`（`i < k < j`） | **更短**的區間 | 依區間**長度**遞增 |

這張表就是完整的決策流程，也就是為什麼 LC 516 的 `i` 要倒著跑、LC 72 的 `i` 要正著跑 — 不是風格，
不是喜好，只是每個遞推式讀到哪些鄰居而已。

#### 表格要開多大 —— `n × n` 還是 `(n+1) × (n+1)`？

| `dp[i][j]` 用的是… | `i` 是… | 大小 | 初始條件放在 | 讀字元的寫法 |
|---|---|---|---|---|
| **字串的實際 index** —— 子字串 `s[i..j]` | 位置 | `n × n` | 對角線 `dp[i][i]` | `s[i]`、`s[j]` |
| **前綴長度** —— 前 `i` 個／前 `j` 個字元 | 數量 | `(m+1) × (n+1)` | 第 0 列／第 0 行 = 空前綴 | `s1[i-1]`、`s2[j-1]` |

**面試記憶技巧**：用實際 index → `n × n`；用「前 `i` 個字元」→ `n + 1`。多出來的那一格只是為了放
*空前綴*。子字串 `s[i..j]`（`i <= j`）永遠不是空的，所以 Shape A 根本沒有東西可以放在那一格。

<!--CODE-->

對照 LC 1143（Shape B）：`dp[i][j]` 是「`s1` 的前 `i` 個、`s2` 的前 `j` 個」，所以 `i` 會跑到 `m`

### 模板 3：區間 DP — LC 312

> 這張表是**形狀 A** — `n × n`、上三角、答案在右上角。它的骨架、兩種合法的填表順序，以及為什麼有
> 切點就只能用依長度驅動的那一種，都在
> [模板 2a](#template-2a-2-d-table-shape-and-fill-order--lc-516-)。

**辨認** — 一次操作的成本取決於**會隨過程改變的鄰居**：「戳破氣球，硬幣 = 左 × 自己 × 右」、
「合併相鄰的石堆，成本 = 兩堆之和」、「把一串矩陣相乘」。n ≤ 300–500 → 這個上限就是為 O(n³)
切點迴圈設的。

**關鍵** — 想的是哪個元素**最後**處理，不是最先處理。當 `k` 是開區間 `(i, j)` 裡最後被戳破的氣球時，
`(i, k)` 和 `(k, j)` 裡的一切都已經消失，所以兩邊是**彼此獨立**的子問題，而 `k` 的鄰居恰好就是 `i` 和 `j`。

- **狀態**：`dp[i][j]` = 戳破 `i` 和 `j` 之間（不含兩端）所有氣球的最大硬幣數
- **遞迴式**：`dp[i][j] = max over i < k < j of dp[i][k] + dp[k][j] + b[i]·b[k]·b[j]`
- **基底**：`dp[i][i+1] = 0` — 裡面什麼都沒有的開區間
- **順序**：區間**長度**遞增（切點讀的是嚴格更短的範圍）
- **答案**：先補成 `b = [1] + nums + [1]`，答案是 `dp[0][n+1]`

### 模板 7：最長遞增子序列 — LC 300 ⭐⭐⭐⭐

> `dp[i]` = 以索引 `i` 結尾的 LIS 長度，答案 = `max(dp)`。O(n log n) 的進階解改成維護一個

### 模板 7a：以值為鍵的 DP（DP + 雜湊表）— LC 1218 ⭐⭐⭐⭐

> **模式**：形狀跟 LIS 一樣的「以這裡結尾的最長鏈」DP，差別在於能排在 `x` **前面**的元素不是

**辨認** — 「相鄰元素相差**固定** `difference` 的最長子序列」、「每一步都是前一個加／減某個已知東西

### 模板 8：編輯距離 — LC 72 ⭐⭐⭐⭐

**模式**：把 `word1` 變成 `word2` 所需的最少插入／刪除／取代次數（Levenshtein 距離）。
辨認清單、三種操作的直覺、由上而下與空間優化的變形，以及圖解表格，都在
[dp_advanced.md](./dp_advanced.md)；整個雙序列家族在 [dp_string.md](./dp_string.md)。
這張表是**形狀 B** — 它的形狀、為什麼照列掃是唯一合法的順序，以及把操作清單還原出來的反向走法，

**辨認** — **兩個字串**，問的是用插入／刪除／取代把一個變成另一個的最低成本，或「讓兩者相等的最少刪除
次數」。m, n ≤ 500 → 一張 O(m·n) 的格子。

**關鍵** — `dp[i][j]` 回答的是 `word1` 的**前 `i`** 個字元與 `word2` 的**前 `j`** 個字元，所以一切由
最後的字元決定：相等 → 免費走對角線；不相等 → 一次操作，再加上它通往的三個鄰居裡最便宜的那個。

- **狀態**：`dp[i][j]` = 把 `word1[:i]` 變成 `word2[:j]` 的最少操作次數
- **遞迴式**：`word1[i-1] == word2[j-1]` 時 `dp[i-1][j-1]`，否則
  `1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])`（刪除、插入、取代）
- **基底**：`dp[i][0] = i`（全部刪掉）、`dp[0][j] = j`（全部插入）
- **順序**：列優先，`i: 1 → m`、`j: 1 → n`
- **答案**：`dp[m][n]`

<!--CODE-->

**複雜度**
- **時間 O(m·n)**：巢狀的 `for i`／`for j` 把 `(m+1)(n+1)` 個格子各填一次，每格 O(1)。
- **空間 O(m·n)**：整張表；第 `i` 列只讀第 `i-1` 列，所以滾動一列就能變成 O(min(m, n))
  （見模板 2a 的*空間壓縮*）。

**推演** — `"horse"` → `"ros"` 的逐格推演，連同它選的路徑，在
模板 2a 的[形狀 B](#shape-b--two-sequences-ij-are-prefix-lengths)（*推演表 — LC 72*）；答案是 `dp[5][3] = 3`。

**陷阱**
- **基底列全是 0。** 把 LCS 的 `dp[0][j] = 0` 抄過來，`"" → "abc"` 的成本就變成 0；編輯距離的基底列是 `j`。
- **用 `word1[i]` 而不是 `word1[i-1]`。** 這張表以長度為索引，所以第 `i` 列決定的字元是 `word1[i-1]`；
  `word1[i]` 在最後一列會讀超出尾端。
- **相等時也收費。** 字元相等時寫成 `1 + dp[i-1][j-1]`，會讓 `"a" → "a"` 的成本變成 1。

**不是這個，如果** — 只允許刪除（LC 583），或目標是最長的共同部分 → LCS
（[模板 9](#template-9-longest-common-subsequence--lc-1143)）；只能刪除時 `edit = m + n − 2·LCS`。
一個序列和它的兩端 → 形狀 A。

**練習** — LC 72 ⭐ · LC 583 *（只能刪除）* · LC 712 *（刪除成本是 ASCII 值）* · LC 161 *（只差一次編輯，
不用表也能 O(n)）* · LC 115 *（計數，而不是成本）*

#### **比較：Edit Distance vs LCS**

LC 72 與 LC 1143 並排對照：

| 面向 | LC 72 (Edit Distance) | LC 1143 (LCS) |
|--------|----------------------|-------------|
| **目標** | **最小化**所需操作數 | **最大化**相符的字元數 |
| **操作** | 插入、刪除、取代 | 只有相符或跳過 |
| **相符時** | 不用付出代價（不需操作） | 長度 +1 |
| **不符時** | 1 + min(三個選項) | max(跳過左邊, 跳過右邊) |
| **DP 轉移** | `dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])` | `dp[i][j] = dp[i-1][j-1] + 1` 或 `max(dp[i-1][j], dp[i][j-1])` |

### 模板 9：最長公共子序列 — LC 1143

**辨認** — 兩個序列，問「它們**依序**共有、但不必連續的最長部分」：「最長公共子序列」、「讓兩個字串
相等的最少刪除次數」、「最多的不相交線」。m, n ≤ 1000 → 一張 O(m·n) 的格子。

不相等 → 至少有一個不在裡面，所以丟掉其中一邊、取較好的那個。

- **順序**：列優先，`i: 1 → m`、`j: 1 → n`

### 模板 10：回文子字串 DP — LC 5 ⭐⭐⭐⭐⭐

**題目原型**：LC 647（Count Palindromic Substrings）、LC 5（Longest Palindromic Substring）

> 這張表是**形狀 A** — 下面那個 `i` 倒著走、`j` 正著走的順序就是
> [模板 2a](#template-2a-2-d-table-shape-and-fill-order--lc-516-) 裡的順序 A；而
> `j - i <= 2` 這個護欄之所以存在，是因為 `dp[i+1][j-1]` 會掉進死掉的三角形裡。

**辨認** — 「最長的／有幾個回文**子字串**」（連續的），或後面的某個 DP 需要以 O(1) 回答「`s[i..j]`
是不是回文？」（LC 131、LC 132）。n ≤ 1000 → O(n²)。

**關鍵** — `s[i..j]` 是回文，若且唯若兩端相等**而且**內部 `s[i+1..j-1]` 也是回文；長度 ≤ 3 的範圍
沒有值得檢查的內部。所以表格由短範圍往外填，`i` 遞減。

- **狀態**：`dp[i][j] = True` 表示 `s[i..j]` 是回文
- **遞迴式**：`dp[i][j] = s[i] == s[j] and (j - i <= 2 or dp[i+1][j-1])`

- **順序**：`i` 從 `n-1` 往下到 `0`，`j` 從 `i` 往上到 `n-1`
- **答案**：LC 5 — `j - i` 最大的 `True` 格子；LC 647 — `True` 格子的數量

### 模板 11：子集上的位元遮罩 DP — LC 1879

**辨認** — 狀態是「我已經用掉**哪個子集**的物品」，而 n 很小：「把 n 個工人各指派到 n 份工作之一」、
「每個節點走訪一次」、「把元素兩兩配對」。n ≤ 14–20 → 預算就是 `2^n` 個遮罩（2²⁰ ≈ 10⁶）。

**關鍵** — 光看遮罩就知道進度到哪：物品照固定順序指派時，`popcount(mask)` 就是下一個要放的索引，
所以 `dp[mask]` 不需要第二個維度，而且每個遮罩都只會從更小的遮罩走過來。

- **狀態**：`dp[mask]` = 把 `nums1[0..k-1]` 與 `mask` 裡的那些 `nums2` 元素配對之後的最小 XOR 和，
  其中 `k = popcount(mask)`
- **遞迴式**：對每個不在 `mask` 裡的 `j`，`dp[mask | 1<<j] = min(…, dp[mask] + (nums1[k] ^ nums2[j]))`
- **基底**：`dp[0] = 0`
- **順序**：`mask` 遞增 — 加一個位元一定會讓數字變大
- **答案**：`dp[(1 << n) - 1]`

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(2ⁿ · n)**：外層 `for mask` 跑 `2ⁿ` 次，內層 `for j` 跑 n 次。
- **空間 O(2ⁿ)**：每個遮罩一格。

| 位元運算 | 意義 |
|--------|---------|
| `mask & (1 << i)` | 物品 `i` 在集合裡嗎？ |
| `mask \| (1 << i)` | 加入物品 `i` |
| `mask ^ (1 << i)` | 移除物品 `i`（只有在它存在時才對） |
| `sub = (sub - 1) & mask` | 枚舉 `mask` 的子遮罩 |
| `bin(mask).count('1')` | popcount = 用掉幾件物品 |

**陷阱**
- **多開一個用不到的索引維度。** 當 `i = popcount(mask)` 時，`dp[i][mask]` 就是同一張表重複 n 次；
  記憶體變成 n 倍，在 n = 20 時可能超過限制。
- **Java 的 `1 << n` 溢位。** 超過 31 個物品的遮罩要用 `long` 和 `1L << n`；n ≤ 20 時 `int` 沒問題，
  但這個習慣很重要。
- **忘了檢查到不到得了。** 從仍然是 `INF` 的遮罩去鬆弛，在 Python 裡是加到無限大（無害），在 Java 裡
  卻是加到 `Integer.MAX_VALUE`，溢位成負數，然後贏下每一次 `min`。

**不是這個，如果** — n 到 40 以上 → `2^n` 不可行；改找貪婪、匹配／網路流，或折半搜尋。物品彼此
可以互換、只有數量重要 → 遮罩縮成一個整數（一般的背包）。

**練習** — LC 1879 · LC 526 *（計數而不是取最小）* · LC 1986 *（工作時段：帶著已用掉的時間）* ·
LC 847 *（在 (node, mask) 上做 BFS）* · LC 1125 *（遮罩是目標：已涵蓋的技能）*

[**dp_bitmask.md**](./dp_bitmask.md) 完整涵蓋：位元運算完整參考、TSP 與指派問題的模板、
子遮罩枚舉 DP、複雜度估算，以及經典陷阱（`n >= 31` 要用 `1L << n`、子遮罩迴圈寫錯、
把 popcount 當索引用）。

### 模板 12：數位 DP — LC 233

**辨認** — 「`[L, R]`（或 `≤ n`）之間有幾個數字滿足某種**位數層級**的性質」：數某個數字出現幾次、
各位數嚴格遞增、沒有重複數字、數位和能被 k 整除。n ≤ 10⁹ 或 10¹⁸ → 範圍大到根本不可能逐一走訪，
但一個數字只有 10–19 位。

**關鍵** — 從左邊開始一位一位地組出數字。只要前綴還等於 `n` 的前綴（`tight`），下一位就被 `n` 的那一位
封頂；一旦比它小，後面每一位都是自由的，所以所有 `(pos, count)` 相同的非 tight 狀態答案都一樣，
可以快取。

| 狀態 | 意義 | 為什麼需要它 |
|-------|---------|---------------|
| `pos` | 正在填第幾位 | 遞迴的索引 |
| `tight` | 前綴是否仍與上界的前綴相同？ | 是的話這一位的上限是 `bound[pos]`；不是的話 `0..9` 隨便填 |
| `started` | 是否已經放過非零數字？ | 用來區分真正的首位數字和補位的零 |

LC 233 數的是數字 `1`，而前導零永遠不會貢獻 1，所以它只需要 `pos`、`tight` 和目前的計數 —
`started` 是給補位的零會破壞的性質用的（「沒有重複數字」）。

### 解題步驟
1. **判斷能不能用 DP**：檢查有沒有重疊子問題

### 常見錯誤與提醒

**🚫 常見錯誤：**
- 狀態定義錯誤
- 漏掉初始條件
- 走訪順序不對
- 沒處理邊界情況
- 資料量大時整數溢位

**✅ 最佳實務：**
- 先寫遞迴解，再做優化
- 畫小例子找出規律
- 仔細檢查陣列邊界
- 先確定正確性，再考慮空間優化
- 狀態變數用有意義的名字

<!-- dd5309fe0277 -->
### 面試提點
1. **從簡單開始**：先寫遞迴解
2. **找出子問題**：畫遞迴樹
3. **加上記憶化**：轉成由上而下的 DP
4. **考慮由下而上**：通常效率更好
5. **優化空間**：用滾動陣列加分
6. **拿例子測**：用小輸入手動推一遍
