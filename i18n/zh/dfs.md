## 總覽
**深度優先搜尋（DFS）** 是一種圖／樹的走訪演算法，沿著每個分支盡可能往深處走，走不下去才回溯。它用遞迴或堆疊來維護走訪路徑。

<!-- 051851fbe209 -->
### 關鍵性質
- **時間複雜度**：圖是 O(V + E)，樹是 O(n)
- **空間複雜度**：遞迴堆疊 O(h)，其中 h = 高度
- **核心想法**：先往深走，再往廣走
- **資料結構**：堆疊（遞迴的隱含堆疊或顯式堆疊）
- **什麼時候用**：路徑搜尋、環偵測、拓撲排序、樹走訪、回溯類題目

### 模板 1：樹走訪 — LC 94 ⭐⭐⭐⭐⭐

**辨識** — 「中序／前序／後序走訪」、「走訪每個節點」、「序列化」、「印出這棵樹」，以及在 BST 裡的
「依排序順序」（BST 的中序就是排好序的）。節點 ≤ 10⁴；遞迴深度等於樹高。

**關鍵** — 三種順序是同一個遞迴，只是*造訪*那一行放的位置不同：
放在子節點之前（前序）、之間（中序）、之後（後序）。不管選哪種順序，每個節點都只進入一次。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(n)**：`dfs` 對每個節點跑一次，對每個空子節點（共 n + 1 個）也跑一次，每次 O(1)。
- **空間 O(h)**：遞迴（或 `stack`）只存一條從根到節點的路徑 — 平衡時 O(log n)，
  退化成一條鏈時 O(n)。

**陷阱**
- `return inorder(node.left) + [node.val] + inorder(node.right)` 在每一層都複製串列：O(n·h)，
  在歪斜的樹上就是 O(n²)。改成往同一個共用串列 append。
- 迭代版**前序**要先推右子節點、再推左子節點，左邊才會先被 pop；先推左邊的話，
  `[1,2,3]` 會回傳 `[1,3,2]`。
- 10⁵ 層深的鏈會撐爆 Python 的遞迴上限；迭代寫法沒有這個限制。

**不適用時** — 要一層一層的順序 → BFS
（[bfs.md § Template 1](./bfs.md#template-1-level-order-bfs--lc-102-)）。節點的答案由子節點的答案
算出來 → [Template 6](#template-6-bottom-up-post-order-dfs--lc-543-)。判斷條件同時需要兩個節點
→ 下面的成對 DFS 變形。

**練習** — LC 94 · LC 144 · LC 145 *（迭代後序 = 反轉「根-右-左」的前序）* ·
LC 100 ⭐ *（成對 DFS）* · LC 101 *（鏡像的成對 DFS：見下方）* · LC 297 ⭐ *（帶 null 標記的
前序）*

#### Symmetric Tree — LC 101

> **關鍵** — 一棵樹對稱的充要條件是它的兩棵子樹互為**鏡像**，所以 DFS 一次帶**兩個游標**
> `(a, b)`，檢查兩者之間的關係：值相等，接著是**外側**那一對 `(a.left, b.right)` 與**內側**那一對
> `(a.right, b.left)`。你往下遞迴時怎麼配對，*就是*這題本身：同向配對 `(a.left, b.left)` +
> `(a.right, b.right)` 就是 LC 100 Same Tree。

**歸約到**：[Template 1](#template-1-tree-traversal--lc-94-) — 對*一對*節點做前序走訪，而不是一個。
來源：[`symmetric-tree.py`](../../leetcode_python/Stack/symmetric-tree.py)。

起手式是 `helper(root.left, root.right)`；根節點本身從頭到尾不跟任何節點比較。三個 base case，
順序如下：兩邊皆空 → `True`；只有一邊空 → `False`；值不同 → `False`。三關都過了才往下走，並讓
`and` 在第一次對不上時短路。

##### 迭代寫法 — 把配對放在堆疊上

題目自己的 follow up 就在問這個寫法，而它也是把成對 DFS 去遞迴化的通用做法：堆疊裡放的是
**一對一對**的節點，推入與彈出都是兩個一起。

<!--CODE-->

- **刻意把 `None` 也推進去。** 跟模板 1 的迭代走訪不同，這裡**不可以**跳過空的子節點：
  `(None, node)` 這種配對一定要被彈出來**比較過**，才能回傳 `False`。用 `if p.left:` 擋住推入，
  會默默地把不對稱的樹判成對稱。
- **彈出時配對是反過來的** — `stack.pop(), stack.pop()` 拿回來的是 `(q.left, p.right)`，
  也就是後推入的那個先出來。這裡無害，因為鏡像述語對它的兩個參數是對稱的；但在述語有方向性的
  成對 DFS（例如「`b` 是不是 `a` 的子樹」）裡就**不是**無害的，那時你必須把兩個值彈進正確的位置。
- **換成配對佇列也完全一樣** — 把堆疊換成 `deque`、連 `popleft()` 兩次；比較的順序會變，答案不會變。
  見 [bfs.md](./bfs.md) 裡的 LC 101 那一列。

**類似題**：
  - LC 100 - Same Tree（同一個骨架，改用*同向*配對）
  - LC 951 - Flip Equivalent Binary Trees（**兩種**配對都試，再 `or` 起來）
  - LC 572 - Subtree of Another Tree（把 LC 100 的成對 DFS 在每個節點重新發動一次）
  - LC 617 - Merge Two Binary Trees（成對 DFS，但**建出**一個節點而不是回傳布林值）
  - LC 1612 - Check If Two Expression Trees are Equivalent（成對走訪 + 比較葉節點的多重集合）
  - LC 226 - Invert Binary Tree（把鏡像當成一個*變換* — 對稱就等於
    `isSameTree(root, invert(root))`，代價是會改動原樹）
  - LC 872 - Leaf-Similar Trees（刻意放進來當對照：兩趟**各自獨立**的 DFS，
    事後比較葉節點序列，因為這題允許兩棵樹的形狀不同）

### 模板 2：圖／網格 DFS（Flood Fill） — LC 200 ⭐⭐⭐⭐⭐

**辨識** — 「島嶼數量」、「連通區域」、「flood fill」、「最大島嶼面積」、
「複製圖」。網格 ≤ 300 × 300，或 V + E ≤ 10⁵ → 一次 O(V + E) 掃過。

**關鍵** — 外層掃描第一次碰到每座島時只會碰到其中一格，而那一格的 DFS 會把相連的陸地全部
淹掉。所以每座島都恰好只在它的第一格被數一次，而每一格只被進入常數次。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(m·n)**：外層掃描每格讀一次，而 `sink` 在遞迴之前就把 `'1'` 改成 `'0'`，
  所以每個陸地格只會進入一次；四個鄰居的檢查都是 O(1)。
- **空間 O(m·n)**：整片都是陸地時就是一座島，遞迴可以深到那個程度。

**陷阱**
- 在四個遞迴呼叫之後才標記：兩個陸地格會互相遞迴到永遠 —
  `[["1","1"]]` 就會撐爆堆疊。
- LC 200 的網格存的是**字元** `'1'` 和 `'0'`；拿整數 `1` 去比，會一座島都找不到。
- 300 × 300 全是陸地就是 9·10⁴ 層深的遞迴：Python 需要 `sys.setrecursionlimit`，或改用 BFS 寫法
  （[bfs.md § Template 3](./bfs.md#template-3-grid-bfs-with-a-direction-array--lc-1091-)）。
- 把網格淹掉會破壞輸入。面試時要講出來，或改用 `visited` 集合。

**不適用時** — 有向圖問「有沒有環」→ 三狀態 DFS
（[graph.md § Template 5](./graph.md#template-5-three-state-dfs-cycle-detection--lc-802-)）；單純的
`visited` 集合會誤報環。兩格之間的最短路線 → BFS。邊一條一條進來 → 併查集。

**練習** — LC 200 ⭐ · LC 733 *（淹一個區域）* · LC 695 *（讓 `sink` 回傳面積）* ·
LC 133 ⭐ *（visited 就是 `{original: copy}` 這張對照表）* · LC 417 ⭐ *（從兩個海洋各自往內淹，
再取交集）* · LC 419 *（完全不用 DFS：見下方變形）*

### 模板 3：路徑搜尋 — LC 112 ⭐⭐⭐⭐⭐

**辨識** — 「根到葉的路徑和」、「路徑是否存在」、「所有路徑」、「從 a 到 b 的
路徑」。節點 ≤ 5,000。

**關鍵** — 路徑狀態（這裡是還需要的和）以參數**往下**傳，所以每個呼叫看到的恰好是從根到自己的
路徑。答案只在葉節點檢查，任一個子節點回傳 True 就立刻往上回傳。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(n)**：每個節點最多造訪一次，`or` 在第一個 True 就停。
- **空間 O(h)**：目前這條根到節點的路徑上，每個節點一個呼叫。

**陷阱**
- 在空的子節點而不是葉節點檢查 `remaining == 0`：`[1,2]`、目標 1 會透過 1 不存在的右子節點
  回傳 True，但唯一一條根到葉的路徑和是 3。
- 空樹沒有任何路徑，目標是 0 也一樣：`hasPathSum(None, 0)` 是 False。
- 在圖的搜尋裡呼叫 `dfs(next)` 卻沒有回傳它的結果：True 找到了又被丟掉
  （見下方的提早回傳一節）。

**不適用時** — 路徑可以在往下的任何地方開始與結束 → 沿路徑的前綴和
（LC 437）。要的是**最短**路徑 → BFS。路徑可以在某個節點轉彎（最大路徑和）→
[Template 6](#template-6-bottom-up-post-order-dfs--lc-543-)。

### 模板 4：回溯 — LC 46

**辨識** — 「所有排列／組合／子集」、「產生每一個合法的 …」、「回傳所有
方法」。n ≤ 10（n! ≈ 3.6·10⁶）或 n ≤ 20（2ⁿ ≈ 10⁶）→ 指數級的搜尋就是預期解法。

**關鍵** — `path` 永遠存著從決策樹的根走到目前呼叫的這一路選擇，每個選擇在試下一個之前都會被撤銷
（`pop`、`used[i] = False`），所以兄弟分支都從同一個狀態出發。

<!--CODE-->

<!--CODE-->

**複雜度**
- **時間 O(n · n!)**：決策樹有 n! 個葉節點，每個以 O(n) 複製；上面的內部節點
  加起來也不超過這個量。
- **空間 O(n)**：`path`、`used` 與遞迴深度，不計輸出。

**陷阱**
- `result.append(path)` 把同一個串列存了 n! 次，搜尋退回去之後它是空的：
  `[1,2]` 會回傳 `[[], []]`。
- 組合（LC 39, LC 77）會傳 `start` 索引，所以 `[1,2]` 和 `[2,1]` 不會同時產生；
  排列則從 0 開始迴圈並跳過 `used`。兩者搞混會產生重複或漏掉順序。
- 輸入有重複（LC 47）：先排序，然後在 `nums[i-1]` 未使用時跳過 `nums[i] == nums[i-1]`。

**不適用時** — 只問排列的**數量**，而且子狀態會重複 → DP。完整家族
（子集、組合總和、N 皇后、剪枝）在 [backtrack.md](./backtrack.md)。

### 模板 5：樹結構修改 — LC 450

**辨識** — 「刪除／插入／修剪／剪掉節點」、「回傳修改後的樹的根」、

**複雜度**
- **時間 O(h)**：一趟從根走到節點，再加一趟沿右子樹往下找後繼 —

### 模板 10：帶權圖 DFS（除法／比值查詢） — LC 399

**辨識** — 「除法求值」、「已知 a / b = 2.0、b / c = 3.0，求 a / c」、「匯率」、
「單位換算」、「傳遞性比值」。變數 ≤ 40、查詢 ≤ 20 → 每個查詢跑一次 DFS
綽綽有餘。

**關鍵** — `a / b = v` 是一條權重 v 的邊 a → b，**也是**一條權重 1/v 的邊 b → a。沿任何
路徑權重相乘、中間項互相抵銷（a/b · b/c = a/c），所以從 x 到 y 的權重乘積
就是 x / y；任何一條路徑都行，因為這些等式是一致的。

<!--CODE-->

**複雜度**
- **時間 O(Q · (V + E))**：每個查詢的 DFS 對每個變數最多造訪一次（`visited`），
  每條邊讀一次。
- **空間 O(V + E)**：圖本身，加上 `visited` 與遞迴的 O(V)。

**陷阱**
- 從沒出現過的變數做 `x / x` 是 -1.0，不是 1.0：LC 399 的查詢 `["x","x"]`。先檢查
  是否存在，再走 `node == target` 的捷徑。
- 所有查詢共用一個 `visited` 集合：第二個查詢會發現節點已被造訪過，
  回傳 -1.0。
- 只存 `a → b`：反方向的查詢（`b / a`）找不到路徑。
- 用 `rest > 0` 而不是 `rest != -1.0` 判斷，是依賴 LC 399 保證值都是正數；
  用哨兵值判斷就不需要這個前提。

**不適用時** — 固定的圖上有很多查詢，或等式一個一個進來 → 帶權
併查集（存每個節點到其根的比值）。成本沿路徑是**相加**而且要最
便宜的 → 最短路徑（[Dijkstra.md](./Dijkstra.md)）。

*（檢查等式之間有沒有矛盾）*

### 常見錯誤與技巧

**🚫 常見錯誤：**
- **忘記 visited 集合**：在圖上會無窮迴圈
- **沒有回溯**：組合類題目會產生錯誤的路徑
- **走訪順序錯誤**：該用後序時卻用了前序
- **邊走訪邊修改**：會破壞迭代
- **沒處理 null**：NullPointerException
- **⚠️ 關鍵：找到路徑時沒有立刻回傳**：在 DFS 裡找路徑時，一找到就必須立刻回傳 true（見 Template 3 底下的提早回傳一節）

**✅ 最佳實務：**
- **在圖上使用 visited 集合**：避免成環
- **複製路徑**：存結果時用 `path[:]`
- **先檢查邊界**：網格類題目
- **取有意義的名字**：用 `visited` 而不是 `v`
- **考慮改成迭代**：遞迴很深的時候
